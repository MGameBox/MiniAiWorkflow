# team-parallel-implement 技能

## 触发时机

- M/L 任务中存在 >=3 个互不依赖的实现切片
- 每个切片都足够独立，值得单独并行编写
- 接口契约、公共类型签名和调用方向已先定义
- 主智能体确认本轮适合直接并行落盘，而不是先走 bootstrap 式保守整合

## 前置条件

主智能体必须先确认：
- [ ] 已定义共享接口契约（公共类型、方法签名、事件约定）
- [ ] 已写出文件分配表（路径白名单）
- [ ] 已确认各子智能体输入互不依赖
- [ ] 已准备集成后验证动作（测试、编译、lint 或最小运行态检查）

## 执行流程

### Step 1: 主智能体定义接口契约与文件分配表

在 spawn 前，主智能体必须先明确：
- 每个子智能体负责哪些文件
- 哪些公共类型或函数签名已固定
- 哪些文件禁止被任何子智能体修改

如果接口契约仍不稳定，应回退到 `team-project-bootstrap` 或串行实现，而不是强行并行落盘。

### Step 2: 加载自定义 Agent 设定（可选但优先）

主智能体为每个实现切片选择合适的角色名，在 spawn 前按以下顺序加载：

1. 尝试读取 `MySkills/agents/{agent-name}.md`
2. **如文件存在**：将全文作为该子智能体的角色 prompt 注入，并在 spawn 前输出：
   ```text
   ✓ 使用自定义定义：MySkills/agents/module-implementer.md
   ```
3. **如文件不存在**：回退到本技能的默认实现角色约束，并输出：
   ```text
   ⚠ 未找到自定义 agent 定义 MySkills/agents/module-implementer.md，使用默认角色描述。
   ```
4. 每个子智能体独立执行此查表步骤，禁止静默回退。

注册约定详见 `MySkills/agents/README.md`。

### Step 3: 并行 spawn N 个实现子智能体

```text
主智能体
  ├─→ Subagent A: 文件白名单 A
  ├─→ Subagent B: 文件白名单 B
  ├─→ Subagent C: 文件白名单 C
  └─→ ...
```

每个子智能体必须获得：
- 自己的文件白名单
- 不可修改文件列表
- 共享接口契约
- 完成后需要回报的修改摘要

**所有 Task 调用同时发出，不串行等待。**

### Step 4: 主智能体集成审查

所有子智能体完成后，主智能体必须：
- 读取全部产出文件
- 检查接口是否一致
- 修正局部集成冲突
- 评估是否需要补一轮串行收尾

### Step 5: 验证

- [ ] 运行最小可执行验证（测试 / 编译 / lint / 类型检查）
- [ ] 如失败，优先修复当前切片的集成问题，再重跑同一验证

## 子智能体约束

- **仅限白名单写入**：不得修改未分配文件
- **禁止跨切片重构**：不得顺手移动、重命名其他子智能体负责的文件
- **完成后必须汇报**：至少返回修改文件列表、关键变更点、未解决问题
- **宿主边界说明**：文件级隔离当前为 prompt 级约定，依赖主智能体定义清楚并做集成复核

## 适用边界

- 适合：接口稳定后的模块并行实现、相互独立的功能切片并行落地
- 不适合：项目启动期骨架未定、接口契约还在快速变化的场景
- 不适合：存在大量跨文件耦合、需要边写边改公共接口的任务
