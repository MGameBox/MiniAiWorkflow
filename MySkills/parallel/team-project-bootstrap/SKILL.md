# team-project-bootstrap 技能

## 触发时机

- 项目源码目录为空或极少（<5 个源码文件）
- 用户确认选择 "启动正式开发"
- 已有核心设计文档（GDD/策划案/需求文档）作为参考基准

## 前置条件

用户必须已确认：
- [ ] 引擎/技术栈已确定
- [ ] 开发环境已就绪
- [ ] 启动方向已确认（最小可玩版本先行，复杂功能后续接入）
- [ ] 从哪个模块切入已确认

## 执行流程

### Step 1: 主智能体读取参考基准

扫描项目根目录判断引擎类型：
- Unity: 存在 `*.csproj` / `Assets/`
- Godot: 存在 `project.godot`
- Unreal: 存在 `*.uproject`
- Web: 存在 `package.json` + 前端框架
- 其他: 根据实际结构判断

读取核心设计文档作为所有子智能体的共享上下文。

### Step 2: 加载自定义 Agent 设定（必须）

在 spawn 每个子智能体前，主智能体按以下顺序加载角色设定：

1. 尝试读取 `MySkills/agents/{agent-name}.md`
2. **如文件存在**：将全文作为该子智能体的角色 prompt 注入，并在 spawn 前输出：
   ```
   ✓ 使用自定义定义：MySkills/agents/engine-setup.md
   ```
3. **如文件不存在**：回退到本技能 SKILL.md 中该角色的默认职能描述，并输出：
   ```
   ⚠ 未找到自定义 agent 定义 MySkills/agents/engine-setup.md，使用默认角色描述。
   ```
4. 三个子智能体各自独立执行此查表步骤，禁止静默回退。

注册约定详见 `MySkills/agents/README.md`。

### Step 3: 并行 spawn 3 个只读实现子智能体

```
主智能体 (Producer & Integrator)
  ├─→ Subagent A: engine-setup
  │     上下文：设计文档技术栈章节 + 项目约定
  │     任务：
  │       - 项目骨架（目录结构、配置文件）
  │       - 场景/项目管理（根据引擎类型：SceneManager/AutoLoad/GameMode等）
  │       - 基础工具类（事件系统、对象池接口、工具函数）
   │     返回：文件清单 + 目录建议 + 核心 API 签名 + 每文件的核心代码建议
  │
  ├─→ Subagent B: core-render
  │     上下文：设计文档 UI/渲染章节 + 现有原型渲染代码（如有）
  │     任务：
  │       - 核心渲染系统（2D/3D场景、主画面、UI框架）
  │       - 输入系统（鼠标/键盘/触摸）
   │     返回：文件清单 + 场景结构建议 + 关键渲染接口 + 每文件的核心代码建议
  │
  └─→ Subagent C: core-gameplay
        上下文：设计文档核心玩法章节 + 现有原型玩法代码（如有）
        任务：
          - 游戏状态管理（状态机、数据模型）
          - 核心玩法规则（最小可玩版本，不含高级功能）
          - 基础 AI/逻辑（如有需要）
      返回：文件清单 + 状态模型建议 + 关键 public API + 每文件的核心代码建议
```

**所有 3 个 Task 调用同时发出。**

### Step 4: 主智能体整合

收集 3 份方案，解决以下整合问题：
- 命名空间/类名冲突
- 接口契约一致性（Subagent A 的项目管理器 vs Subagent C 的状态管理）
- 目录结构统一

### Step 5: 统一写入

主智能体按整合后的方案一次性写入所有文件。

**写入前必须**：
- 展示完整的文件清单和目录结构
- 等用户确认

### Step 6: 验证

- [ ] 项目能编译/运行无报错
- [ ] 核心画面能正常显示
- [ ] 最小可玩版本能运行（核心交互正确）

## 子智能体约束

- **只读不写**：子智能体只有 Read 权限，返回方案、接口与代码建议给主智能体
- **上下文隔离**：每个子智能体只加载自己需要的参考文件
- **接口契约**：涉及跨模块接口时，子智能体必须显式写出 public API 签名

## 模式说明

`team-project-bootstrap` 采用 **Producer-Consumer** 模型：

- 适用于项目启动期，目录骨架与接口契约仍在快速收敛
- 子智能体并行产出方案和关键代码建议，但不直接落盘
- 主智能体统一整合后写入，避免多个子智能体在启动期对同一骨架做相互覆盖

## 迭代边界

本次技能只负责**最小可玩版本**的实现。
高级功能、复杂系统、 polish 作为后续迭代，不在本次范围内。
