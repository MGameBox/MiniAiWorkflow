# team-parallel-analyze 技能

## 触发时机

- L 级任务前期，需要同时分析 >=3 份不相关文档
- 需并行摸底 >=2 个相对独立模块的代码边界
- 主智能体已确认本轮目标是分析，不直接进入写入实现

## 前置条件

主智能体必须先确认：
- [ ] 已定义本轮分析问题，而不是笼统“都看看”
- [ ] 已完成分析切片，每个子智能体有独立输入范围
- [ ] 已确定最终汇总格式，避免各子智能体返回不同结构
- [ ] 本轮不要求子智能体直接修改文件

## 执行流程

### Step 1: 主智能体划分分析切片

为每个子智能体明确：
- 输入文件列表或文档范围
- 分析目标（边界/风险/依赖/一致性/缺口）
- 输出格式（摘要、风险点、边界条件、待确认问题）

切片之间应尽量互不依赖，避免一个子智能体等待另一个子智能体的中间结论。

### Step 2: 加载自定义 Agent 设定（可选但优先）

主智能体为每个分析切片选择合适的角色名，优先复用现有自定义 agent（如 `tech-lead`、`doc-engineer`、`pm`）。在 spawn 前按以下顺序加载：

1. 尝试读取 `MySkills/agents/{agent-name}.md`
2. **如文件存在**：将全文作为该子智能体的角色 prompt 注入，并在 spawn 前输出：
   ```text
   ✓ 使用自定义定义：MySkills/agents/tech-lead.md
   ```
3. **如文件不存在**：回退到本技能的默认分析角色约束，并输出：
   ```text
   ⚠ 未找到自定义 agent 定义 MySkills/agents/tech-lead.md，使用默认角色描述。
   ```
4. 每个子智能体独立执行此查表步骤，禁止静默回退。

注册约定详见 `MySkills/agents/README.md`。

### Step 3: 并行 spawn N 个只读子智能体

```text
主智能体
  ├─→ Subagent A: 分析切片 A
  ├─→ Subagent B: 分析切片 B
  ├─→ Subagent C: 分析切片 C
  └─→ ...
```

每个子智能体只负责自己的切片，输出必须包含：
- 关键发现
- 风险点
- 边界条件
- 待主智能体统一确认的问题

**所有 Task 调用同时发出，不串行等待。**

### Step 4: 主智能体统一汇总

主智能体负责：
- 合并重复发现
- 标注相互矛盾的结论
- 提炼统一建议
- 判断是否需要进入计划、实现或 review 阶段

推荐汇总格式：

```markdown
## 并行分析汇总

### 切片 A
- 关键发现：
- 风险点：

### 切片 B
- 关键发现：
- 风险点：

### 汇总结论
- ...

### 待确认问题
- ...
```

## 子智能体约束

- **只读不写**：子智能体不得使用 Write/Edit 工具修改文件
- **局部上下文**：每个子智能体只读取被分配的切片，避免上下文污染
- **结构化返回**：不得只返回大段原文摘抄，必须提炼分析结论
- **禁止越权扩张**：本模式只做分析，不直接转入编码或文档改写

## 适用边界

- 适合：多文档摸底、跨模块边界盘点、计划前风险分析
- 不适合：需要统一接口设计后再并行编码的实现任务
- 不适合：文件数量很少、主智能体单独阅读更便宜的小范围问题
