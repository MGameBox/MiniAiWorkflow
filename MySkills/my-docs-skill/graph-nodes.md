# MyDocsSkill Graph Nodes

## 目标

定义项目图谱节点的最小职责，避免把 `ProjectGraph` 扩张成低价值文库。

## 推荐节点

- `Docs/ProjectGraph/项目总览.md`
- `Docs/Indexes/地图-MOC.md`（可选，仅在项目显式启用 MOC 增强层时创建）
- `Docs/Templates/项目图谱模板.md`

## 节点职责

### 项目总览

- 只记录项目主线、核心模块和关键链路。
- 作为最高层图谱节点，不下沉到细碎代码级别。

### 地图-MOC（可选）

- 仅在项目显式启用 MOC 增强层时承担补充导航职责。
- 当前默认总导航仍以 `Docs/README.md` 为准，不负责承载完整结构认知。

### 项目图谱模板

- 提供新增图谱节点时的轻模板。
- 保持节点风格稳定，避免每次任务写成不同格式。

## 何时新增节点

- 模块边界发生变化。
- 出现新的稳定入口或关键链路。
- 当前结构认知如果不记录，后续协作成本会明显升高。

## 不建议的做法

- 为单次 bug 建独立图谱节点。
- 为了图谱漂亮而复制大量代码细节。
- 用图谱节点替代正常计划、日志和架构文档。
